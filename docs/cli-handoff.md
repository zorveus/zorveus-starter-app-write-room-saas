# Starter contract for CLI launch

The bundled manifest is `zorveus.json`. It passes the existing CLI schema at checkout `fa39a36`. It defines `plus` at $10 USD per customer monthly and `plus_ultra` at $30 USD per customer monthly, with the shared `customers` service key. Both policies use 100 credit units per USD, enforced credits, and `limit_output`. The main demo uses direct plan credentials and includes no routing key. The only service scope is `product_users:read`; the reviewed backend supports explicit first-read creation with that scope.

The app uses the server variables in [the environment reference](configuration.md#server-environment). Both endpoint variables must be injected together for local configuration. Inject `keys.plus` as `ZORVEUS_PLUS_INFERENCE_KEY` and `keys.plus_ultra` as `ZORVEUS_PLUS_ULTRA_INFERENCE_KEY`. Both direct credentials must be available and distinct. The old shared `ZORVEUS_INFERENCE_KEY` variable is not used. Alex has a trusted Plus assignment and Sam has Plus Ultra. The server selects the same direct key for generation and allowance reads, with no alias. The default model is `gemini/gemini-3.5-flash-lite`, which must be allowed by `app.allowedModels`; the server accepts `ZORVEUS_MODEL_ID` as an override. No manifest schema extension is needed.

App startup uses `npm run dev` with server-only configuration from `.env` or the process environment. The CLI-backed launcher was removed at the user's request. The app does not call whoami or retrieve at startup and does not access the OS credential store. Resource planning and approved apply remain separate CLI operations.

Joint acceptance still requires an authorized fresh-account flow using this manifest: plan, inspect, apply, launch with the developer’s configured server environment, one real attributed rewrite, selected Plus allowance, matching Activity, a second independent customer on Plus Ultra, a controlled allowance denial, and an unchanged repeat plan. Do not substitute an init- or wizard-generated manifest for this check. Do not print credentials or forward them through agent messages.
